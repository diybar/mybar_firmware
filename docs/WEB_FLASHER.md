# MyBar Web Flasher

The web flasher lets anyone install the MyBar firmware on an ESP32 board from a browser, with nothing more than a USB cable. It is published automatically at

**https://diybar.github.io/mybar_firmware/**

and always offers the firmware from the latest build of `main`.

Related documents:

* [CI_CD.md](CI_CD.md) — the pipeline that builds the firmware and deploys this page
* [FIRMWARE_UPDATE.md](FIRMWARE_UPDATE.md) — updating a board that already runs MyBar over Bluetooth

---

## 1. For users: flashing a board

### Requirements

* **Browser:** Chrome, Edge or another Chromium based browser on Windows, macOS or Linux. Safari, Firefox and all mobile browsers lack the Web Serial API and show "Your browser cannot talk to serial ports".
* **Cable:** a USB *data* cable. Many cheap cables carry power only; if no port shows up, try another cable first.
* **Driver:** most ESP32 dev boards use a CP2102 or CH340 USB-to-serial chip. Windows 10/11 and macOS usually install it automatically. If not: [CP210x driver](https://www.silabs.com/developers/usb-to-uart-bridge-vcp-drivers), [CH340 driver](https://www.wch-ic.com/downloads/CH341SER_ZIP.html).

### Steps

1. Open https://diybar.github.io/mybar_firmware/. The card shows *Installs firmware vX.YZ*.
2. Plug the board into the computer.
3. Click **Install MyBar firmware**. The browser opens a port chooser; select the board's port (named after the USB chip, for example *CP2102 USB to UART Bridge* or *USB-SERIAL CH340*).
4. The flasher connects and asks what to do:
   * **Install MyBar** — writes the firmware, keeps the rest of the flash.
   * **Erase device and install** — wipes the whole chip first. Choose this for a new board, a board that ran different firmware, or when in doubt. It also clears the EEPROM settings (board order, motor count, etc.), which the app will set again.
5. Wait for *Installation complete* (30 to 60 seconds). The board reboots and starts advertising over Bluetooth as usual. Close the dialog.

The dialog also offers **Logs & Console**, a serial monitor at 115200 baud. Useful to confirm the board boots and to see the debug output.

### When something goes wrong

| Problem | What to try |
|---|---|
| No port in the chooser | Different cable, different USB port, no hub. Install the driver for the board's USB chip. |
| "Failed to open serial port" | Another program owns the port: close the Arduino IDE, PlatformIO, serial monitors and the MyBar desktop tools. |
| Stuck on "Connecting" or "Failed to initialize" | Hold the **BOOT** (IO0) button while clicking Install, release once flashing starts. Some boards also need a tap on **EN**/RESET while holding BOOT. |
| Page says HTTPS is required | Web Serial only works on secure origins. Use the `https://` address, not a `file://` copy. |
| Flash completes but the board does not appear in the app | Power-cycle the board. Open *Logs & Console* to confirm it boots; if it reboots in a loop, run *Erase device and install* once. |
| Slow flashing | Normal at 115200 baud is about a minute. The flasher tries 921600 first and falls back if the adapter cannot keep up. |

### When to use this page versus the app

* **First installation, boards on firmware 1.95 or older, or a board that no longer boots:** use this page.
* **Boards already on 1.96 or newer:** the MyBar app updates them over Bluetooth, no cable needed. See [FIRMWARE_UPDATE.md](FIRMWARE_UPDATE.md).

## 2. How it works

The page is a single static file, [`web/index.html`](../web/index.html), that loads [ESP Web Tools](https://esp-web-tools.github.io/) from a CDN:

```html
<script type="module" src="https://unpkg.com/esp-web-tools@10/dist/web/install-button.js?module"></script>
...
<esp-web-install-button manifest="manifest.json">
  <button slot="activate">Install MyBar firmware</button>
  <span slot="unsupported">...</span>
  <span slot="not-allowed">...</span>
</esp-web-install-button>
```

ESP Web Tools bundles `esptool-js`, a JavaScript port of Espressif's `esptool`. When the user clicks the button it:

1. asks the browser for a serial port (Web Serial API),
2. resets the board into the ROM bootloader through the DTR/RTS lines,
3. detects the chip and checks it against `chipFamily` in the manifest,
4. writes every `part` from the manifest at its `offset`,
5. resets the board into the new firmware.

Everything happens in the browser. The firmware is downloaded from the same site; nothing about the user or the board is sent anywhere.

### Files on the site

The Pages job in the pipeline assembles the site from the `web/` folder and the build output:

```
https://diybar.github.io/mybar_firmware/
├── index.html                      web/index.html
├── manifest.json                   generated by scripts/build.sh
├── version.json                    generated by scripts/build.sh
└── firmware/
    ├── mybar-<v>.bin
    ├── mybar-<v>.merged.bin
    ├── mybar-<v>.bootloader.bin
    ├── mybar-<v>.partitions.bin
    ├── boot_app0.bin
    ├── SHA256SUMS
    └── MD5SUMS
```

### The manifest

`manifest.json` follows the [ESP Web Tools manifest format](https://esp-web-tools.github.io/#manifest). It is generated for every build so the version and file names are always right:

```json
{
  "name": "MyBar",
  "version": "1.96",
  "new_install_prompt_erase": true,
  "new_install_improv_wait_time": 0,
  "builds": [
    {
      "chipFamily": "ESP32",
      "parts": [
        { "path": "firmware/mybar-1.96.bootloader.bin", "offset": 4096 },
        { "path": "firmware/mybar-1.96.partitions.bin", "offset": 32768 },
        { "path": "firmware/boot_app0.bin",             "offset": 57344 },
        { "path": "firmware/mybar-1.96.bin",            "offset": 65536 }
      ]
    }
  ]
}
```

| Field | Meaning |
|---|---|
| `chipFamily: "ESP32"` | Only the original ESP32 is accepted. Plugging in an ESP32-S3 or C3 shows an "unsupported chip" error instead of writing a wrong image. |
| `new_install_prompt_erase` | Offer the *Erase device* choice on a first install. |
| `new_install_improv_wait_time: 0` | After flashing, do not wait for an Improv Wi-Fi handshake. MyBar uses BLE and has no Improv support, so waiting would only add a 10 second delay. |
| `parts` | The four pieces the Arduino IDE also writes, at the standard ESP32 offsets: bootloader `0x1000`, partition table `0x8000`, `otadata` initialiser `0xE000`, application `0x10000`. |

Why four parts instead of the single `merged.bin`? The merged image is padded to the full 4 MB and would take four times longer to write. The four parts total about 1.2 MB and produce an identical flash layout.

### `version.json`

The page fetches `version.json` to fill in the version badge and the *Details for app developers* table (OTA image name, size, MD5, ready-made `otaStart:<size>:<md5>` command, build time and commit). The same file is a release asset. Its format is documented in [CI_CD.md](CI_CD.md#24-versionjson).

## 3. For maintainers

### Editing the page

Edit `web/index.html` and merge to `main`; the Pages job redeploys it with the current firmware. There is no build step, framework or dependency to install. Keep it a single file so it stays easy to review and to host elsewhere.

The links in the footer and in the script point at `github.com/diybar/mybar_firmware`. Update them if the repository moves.

### Testing locally

Web Serial needs a secure origin, but `http://localhost` counts as secure, so a local server works:

```
bash scripts/build.sh
mkdir -p site && cp -r web/. site/ && cp dist/manifest.json dist/version.json site/ && cp -r dist/firmware site/
python -m http.server 8000 --directory site
```

Open http://localhost:8000/ in Chrome and flash a real board. Opening `index.html` directly from disk (`file://`) does **not** work.

### Hosting somewhere else

The site is fully static. Copy the same file layout to any HTTPS host. Two requirements:

* `manifest.json` and the `firmware/` files must be served from the same origin as `index.html`, or with `Access-Control-Allow-Origin` headers, because ESP Web Tools fetches them with `fetch()`.
* The binaries must be served with their exact bytes (no compression rewriting, no HTML error pages for missing files).

### Offering more than one version

ESP Web Tools shows exactly what one manifest describes. To offer several versions, host one manifest per version (for example `manifests/1.96.json`) and add a `<select>` that sets the `manifest` attribute of the button before the user clicks it. The pipeline currently publishes only the latest build; older binaries are on the [releases page](https://github.com/diybar/mybar_firmware/releases).

### Pinning ESP Web Tools

The page loads `esp-web-tools@10`, which follows the latest 10.x release. Pin to an exact version (`esp-web-tools@10.4.0`) if an upstream change ever breaks the page, and check the [changelog](https://github.com/esphome/esp-web-tools/releases) before moving to a new major.
